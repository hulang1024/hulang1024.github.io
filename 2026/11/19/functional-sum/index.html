在clojure中用函数式方法计算1+2+..10

发表于 2026-11-19

1+2+..10代表了一类问题。在面向过程语言中，通常这样来计算1+2+..10：

执行流程是，首先执行初始化acc = 0, i = 1，然后检查迭代/循环结束条件i <= 10，如果没有结束，每次循环都会执行不变式acc += i; i += 1，直到i > 10。
在每次循环中，我们用i+1和acc+i计算出一个新值再通过赋值去修改i和acc。
这里的i和acc就像在草稿纸上的两个数，我们先拿到纸上“当前”acc和i的值，然后计算新的值，再擦除旧值，把新的数写上去。

递归

我们定义了一个函数sum，可以被复用（在这里是被自身调用），在函数体中，recur关键字等同于sum（就像对象方法中的this）。
同样，我们定义了一个不变式(if ...)，在(<= i 10)为真时，则执行调用sum，于是形成了循环的效果。如果i大于10，将直接返回acc的值并不再调用sum，则循环结束。
初始化的地方是在第一次调用(sum 0 1)，它让acc=0,i=1。在每次迭代中，我们计算出新的acc和i的值，但这里我们这里没有去“修改”变量的值。
而是就像第一次调用sum那样，进行一次新的调用：(sum 1 2)，来初始化一次局部变量acc和i，后续不会修改它们。
对于上面描述的这个过程，可以想象有10张纸，我们不会擦除每一张纸上的acc和i旁边写着的数，而是在新的纸上写下新的acc和i的数。（实际上，尾递归优化会复用旧的纸，但不妨碍我们进行那样的推理）

loop

loop 是上面的sum的简化写法。(sum 0 1)和定义参数放在一起写变成了[acc 0 i 1]。

loop 集合

我们这里只是将i的历史值序列替换成了集合。

reduce

就对于本问题的类似问题而言，不需要写模板代码，而是通过调用库函数reduce，reduce抽象了loop、遍历集合，初始化、不变式。需要填空reduce参数即可，只需要极少的代码。

至此为止，我们消除了for、while、变量acc和i，和对它们的mutation。
这样做的好处是，避免关注繁多细节，从而避免犯错的机会。

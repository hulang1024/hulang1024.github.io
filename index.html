如何实现冒泡排序算法？如何用函数式范式来实现。最重要的不是这个简单算法本身，而在于思考这类问题带来的收获。

函数式

在仔细回忆冒泡算法的基本过程之后，我有信心写出一个过程式的命令式的程序：一个双层循环，在内层循环中将较大的数到移到最右边（假如是从小到大）。
但既然正在学习函数式，如何用函数式的视角来解？对于我来说，使用函数式，意味着一种不同的思维，不再通过去修改状态的方式来达成预期结果，而是直接想象一个结果。
通过观察命令式版本的双层循环，我们可以发现，它是为了构造一个循环（废话）：生成一个j的序列，然后用这个j去遍历数组，更改数组。也就是说，循环在这里的作用有两个：生成j序列，原地更改数组。

在clojure中用函数式方法计算1+2+..10

发表于 2026-11-24

1+2+..10代表了一类问题。在面向过程语言中，通常这样来计算1+2+..10：

执行流程是，首先执行初始化acc = 0, i = 1，然后检查迭代/循环结束条件i <= 10，如果没有结束，每次循环都会执行不变式acc += i; i += 1，直到i > 10。
在每次循环中，我们用i+1和acc+i计算出一个新值再通过赋值去修改i和acc。
这里的i和acc就像在草稿纸上的两个数，我们先拿到纸上“当前”acc和i的值，然后计算新的值，再擦除旧值，把新的数写上去。

递归

我们定义了一个函数sum，可以被复用（在这里是被自身调用），在函数体中，recur关键字等同于sum（就像对象方法中的this）。
同样，我们定义了一个不变式(if ...)，在(<= i 10)为真时，则执行调用sum，于是形成了循环的效果。如果i大于10，将直接返回acc的值并不再调用sum，则循环结束。
初始化的地方是在第一次调用(sum 0 1)，它让acc=0,i=1。在每次迭代中，我们计算出新的acc和i的值，但这里我们这里没有去“修改”变量的值。
而是就像第一次调用sum那样，进行一次新的调用：(sum 1 2)，来初始化一次局部变量acc和i，后续不会修改它们。
对于上面描述的这个过程，可以想象有10张纸，我们不会擦除每一张纸上的acc和i旁边写着的数，而是在新的纸上写下新的acc和i的数。（实际上，尾递归优化会复用旧的纸，但不妨碍我们进行那样的推理）

我为什么使用Clojure

发表于 2026-11-24

它是Lisp。Clojure是一种实用的Lisp方言，对于已经用过Scheme，Racket等Lisp的人来说，它是一个可以尝试的选项。

Clojure基于JVM，Clojure的兄弟ClojureScript，则可以编译为JavaScript。两者分别利用Java和JavaScript生态，不必担心其语言小众生态薄弱，你可以调用很多库，利用很多工具。两者(以后简称clj)语言核心相同，对于熟悉Java和JavaScript的人来说，它值得去尝试。

函数式语言。clj与Java和JavaScript等语言不同的是，它是一个函数式语言，因为它的默认选项是：数据结构默认不可变、有一个完善的函数式核心标准库等。引导你在这个框架下思考问题与解决问题，因此它是一个训练场，通过它学习到真正的函数式范式。在这之前，我仅仅把Scheme和Racket当成有着简洁语法的Lisp语言，去编写过程式和面向对象结构的程序。

性能。clj实现了“持久化数据结构”，通过共享结构，使得“修改”也很高效。

实用主义。与Haskell相比，在函数式这点它不太纯粹，为了实用性而妥协，实用性也是我选择它的原因之一。

语法简洁。跟所有Lisp方言一样，它的语法特别简洁，写出的程序噪音特别少，clj学习起来也尤其简单。

丰富的数据集合类型。clj有着丰富的数据集合类型，而不用重复发明，减少了社区方案分裂带来的麻烦。有：list、vector、set、map等。与scheme不同，clj多了vector、set和map，它们通常用来表示应用领域数据模型，list则通常只用来表示语法结构，来供宏操作。

REPL。REPL是Clojure社区交互式、探索式开发的核心工具。

还有其他好处，例如为并发设计，更多信息推荐你到官网中了解。
